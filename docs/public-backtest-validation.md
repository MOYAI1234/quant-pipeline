# 公开回测平台交叉验证

本文用于把项目内回测结果与聚宽、优矿、米筐等公开平台进行可审计对照。目标是发现数据与成交假设差异，不是追求两套引擎逐分逐厘完全一致。

## 进入条件

- `python scripts\verify_offline.py` 通过。
- 使用真实历史 provider 导出输入，记录来源、获取时间和复权口径。
- 回测参数、策略版本和产物 manifest 已归档。
- 不包含 API key、token、账户信息或受许可限制的行情文件。

## 网格策略附加门槛

- 使用实际券商买卖费率和单笔最低佣金，不以零费用结果作为结论。
- 设置合理滑点和成交量参与率，不采用无限流动性假设。
- 记录单轮网格毛收益、费用、滑点和净收益。
- 参数频率必须符合 ETF 投资助手定位；依靠高密度成交才能盈利的参数判定为不可进入生产预研。
- 进行费用、滑点和网格间距敏感性测试，确认结论不是单一参数点偶然成立。

## 通过标准

只有同时满足以下条件，才可进入模拟盘或小资金实盘预研：

1. 关键调仓方向与持仓变化一致，无法对齐的差异有明确解释。
2. 收益和回撤差异可以由已记录的数据、费用或撮合假设解释。
3. 使用保守费用和滑点后，策略结论没有反转。
4. 网格策略不依赖高密度交易或不现实的成交假设。
5. 内部回测产物、公开平台结果和差异说明均已归档。

通过公开平台交叉验证仍不等于可以生产实盘。下一阶段还需要模拟盘、小资金门禁、真实订单状态机、kill switch 和运行审计。
